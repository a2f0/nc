# Development

Start with the [quick start](../README.md#quick-start), then each platform's README for
building it ([iOS](../ios/README.md), [Android](../android/README.md), [web](../web/README.md)).
[AGENTS.md](../AGENTS.md) defines the full validation and shipping requirements;
[dependency maintenance](dependency-upgrades.md) covers upgrades.

## Setup

The quick start installs the pinned tools, dependencies, and Git hooks. The full local gate
(`bun run check`) also builds both native apps, so it needs Xcode and the Android SDK. The web
integration tests need Playwright's Chromium, and the [screenshots](#screenshots) need
ImageMagick and Maestro:

```sh
bun x --no-install playwright install --with-deps chromium   # web integration tests
brew install imagemagick                                      # screenshots only
curl -fsSL https://get.maestro.mobile.dev | bash              # screenshots only
```

## Repository layout

Keep application code and its focused tooling in `ios/`, `android/`, `web/`, and `l10n/`.
Store lanes and their helpers, tests, and metadata remain together in `fastlane/`.
The [script directory](../scripts/README.md) groups other repository-owned commands by
purpose. Update callers, relative paths, native build inputs, tests, and documentation
when moving a script. Package scripts remain the normal entrypoints where available.

Shared workflow commands and managed skills come from the exact-pinned agent-tool;
keep nc-specific policy in `agent-tool.json` and the application gate in its hooks/CI.
The managed skills in `.agents/skills` and `.claude/skills` and the harness permission rules in
`.claude/settings.json`, `.codex/rules/agent-tool.rules`, and `.agent-tool-permissions.json` are
generated by `bun run agents:sync`; don't edit them.
Repository-owned skills, such as [app-store-readiness](../skills/app-store-readiness/SKILL.md),
live in `skills/`.
Detailed application behavior lives in [architecture](architecture.md), language
maintenance in [localization](localization.md), and publishing in [releasing](releasing.md).

### Module layers

The TypeScript modules form layers, lowest first; each imports only its own layer and those
below it, and no module imports itself around a cycle, type-only imports included:

1. `l10n/` (outside its `test/`): the string catalog, translations, and generators.
2. `web/src/`: the web app, which imports `l10n/` directly.
3. `web/*.ts`: the web build, development server, and Worker.
4. `fastlane/`, `scripts/`, and the rest of `web/`: tools.

Tests (`*/test/`, `*.test.ts`) may import any layer, but no other module may import them.
`bun run lint:module-graph` runs `agent-tool graph check` over the `graph` section of
`agent-tool.json`, which holds these layers; `bun run check` and CI run it. A new production
file outside every layer fails it too. Put a type or constant two modules share in a lower
module both import, as `l10n/catalog.ts` does for `l10n/build.ts` and `l10n/languages.ts`.

## No binary files

Nothing binary is committed; the hooks reject it (`bun run lint:binary-files`).

**Images** are generated from two SVGs in `assets/brand/`, and the outputs are gitignored:

| Source | Becomes |
|---|---|
| `assets/brand/logo.svg` | The mark, an LCD equalizer drawn full-bleed so its columns touch the icon's bottom edge: the iOS app icon and launch screen logo; the Android adaptive icon foreground, themed (monochrome) icon, and notification icon; the favicon; the logo beside each app's title; the website's social preview image; the Play Store icon and feature graphic |
| `assets/brand/background.svg` | The iOS app icon backdrop and full-bleed launch screen; the Android adaptive icon background and splash color; the favicon, title logo, social preview image, and Play Store graphics |

The `images` section of `agent-tool.json` declares every output's size, layers, and
destination, and `agent-tool images` renders them
([reference](https://github.com/a2f0/agent-tool/blob/main/docs/images.md)), with no image
tools to install. Builds regenerate them when the sources change (an Xcode build phase and a
Gradle task before `preBuild`), or run `sh scripts/build/buildImages.sh`; `web/build.ts` writes the
favicon and social preview image, and the `android listing` lane the Play Store graphics. To look at those, run
`sh scripts/build/buildImages.sh store --out .store-graphics/android` (`--out` is relative to the
repository root; `.store-graphics` is gitignored). Store graphics render in each clone and never
go in `.screenshots`, which may be a link that `agent-tool images` refuses to write through. Android 12+ splash screens only take a solid color, so Android uses the
background's average color there. Android adaptive icons show the inner 72dp of a 108dp layer,
which the mark fills; its bottom row is stretched to the layer's edge so the columns still
reach the bottom under any launcher mask. Single-color renders (themed and notification icons),
the favicon, and the title logo leave out the mark's `unlit` group of dim segments.

**The Gradle wrapper jar** is regenerated by `scripts/dev/ensureGradleWrapper.sh`.

## Git hooks

`bun run hooks:install` installs the three hook bodies declared in `agent-tool.json`;
rerun it after hooks change. `bun run hooks:check` checks every managed file, and
pre-push also compares its own copied body so stale hooks cannot gate a push.

When migrating an existing clone from the old installer, inspect its effective hook
directory (`git config --path core.hooksPath`, or the common Git directory's `hooks/`).
After confirming the installed files are the expected repository copies, run
`bun run hooks:install --adopt` once. The shared installer backs them up and preserves
unknown hooks; resolve local hook edits before adoption. Later installs omit `--adopt`.

- **pre-commit:** branch name is `<type>/<name>` (or `main`); detached commits during
  a rebase skip the branch-name check; no binary files staged.
- **commit-msg:** Conventional Commits, header at most 50 characters, lowercase subject.
- **pre-push:** commits are signed with no `Co-authored-by` trailers; no binary files;
  ShellCheck; RuboCop; ktlint; SwiftFormat and SwiftLint; shared agent skills and permission
  rules are current; localization is current; fastlane helper, web, localization, and workflow
  adapter tests; web typecheck, build, and deploy dry run; Android debug build, lint, unit tests,
  and detekt; iOS simulator build, audio rendering checks, and player lifecycle tests on an
  isolated simulator.

Branch names use the configured Conventional Commits types, with `main` exempt and no
additional length cap. Native Git ref rules also apply. Commit headers keep the existing
50-character limit, lowercase initial subject, no terminal period, and generated-message
exemptions. A small commit-message adapter preserves nc's lowercase scope grammar,
counts the whole header including a PR suffix, and skips leading blank/comment lines
before applying shared policy. Signatures must be present and not provably bad;
local key trust is not required.

Pre-push validates every destination branch from Git's ref tuples. Trust checks exclude
commits reachable from all of the named remote's tracking refs, including other published
feature branches, even for an existing branch update,
so integrating previously published mainline commits does not revalidate historical policy.
New local commits still undergo signature, attribution, and subject checks. URL-only pushes
use their remote tip, or local `main` for a new branch, because they have no named tracking refs.

`bun run check` keeps the full application gate in `scripts/testing/check.json` and records
per-step logs and source fingerprints. A failed command or changed source fails the group.
Use `bun run agent-tool runs list --head <commit>` to find stored receipts. CI passes the actual
PR branch explicitly and runs the same checks; `CI gate` remains the single required check,
with every lint, Android, iOS, and web job required to succeed.

## Native code quality

Every tool below fails the gate on any finding, warnings included, both in pre-push and in CI.

| | Kotlin (`android/`) | Swift (`ios/`) |
|---|---|---|
| Compiler | `allWarningsAsErrors` and `extraWarnings` (`app/build.gradle.kts`) | Swift 6 language mode; warnings as errors, `ExistentialAny`, `MemberImportVisibility`, and strict memory safety (`ios/Config/Base.xcconfig`; `testIosAudio.sh` compiles its harnesses the same way) |
| Formatting | ktlint, `intellij_idea` style at 120 columns, as Android Studio formats with `kotlin.code.style=official` (`.editorconfig`) | SwiftFormat at 120 columns (`.swiftformat`) |
| Linting | Android Lint with every check on and tests included, plus Slack's [Compose rules](https://slackhq.github.io/compose-lints/) (`app/lint.xml`); detekt with type resolution (`app/detekt.yml`) | SwiftLint `--strict` with a curated set of opt-in rules, including accessibility and force unwrapping (`.swiftlint.yml`) |

`bun run lint:kotlin` and `bun run lint:swift` check formatting and style;
`bun run format:kotlin` and `bun run format:swift` fix what the tools can. Detekt and Android
Lint run in Gradle: `(cd android && ./gradlew lintDebug detektMain detektTest)`, with reports in
`android/app/build/reports/`. The tools are pinned in `.mise.toml` and the version catalog.

The configs record each exception with its reason: version checks that would fail whenever a
newer release appears, generated images, and rules that don't apply to Compose, Robolectric, or
the noise generators' published coefficients. Files that `bun run l10n` generates
(`AppLanguage.swift`, `Language.kt`) are excluded from formatting. In code, suppress a single
finding at its site with the reason beside it, rather than adding a baseline.

## Screenshots

```sh
bun run screenshots [ios|android]   # default: both
```

Needs Maestro, ImageMagick, jq, Xcode with the iOS 26.2 simulator runtime
(`IOS_SCREENSHOT_RUNTIME_VERSION` picks another), and the Android SDK with its emulator and
command-line tools (see [setup](#setup)). Maestro drives one device at a time on a machine,
so don't start a capture while another Maestro run is going.

Drives the app with the Maestro flows in `maestro/screenshots/` on dedicated simulators and
a headless emulator, with a fixed 9:41 status bar, in light and dark appearance. Android
runs the minified release build, signed with the debug key. Writes store-sized PNGs (no
alpha) below the gitignored `.screenshots` (or `SCREENSHOT_OUTPUT_DIR`): iPhone 6.9"
(1320x2868), iPad 13" (2064x2752), and Android phone (1080x1920, within Google Play's 2:1
limit). iOS captures use the full rectangle without black device corners.

```text
.screenshots/
  capture.json                 # shared capture record (see below)
  ios/iphone/01-home.png, 02-playing.png, 03-playing-dark.png
  ios/ipad/01-home.png, 02-playing.png, 03-playing-dark.png
  ios/maestro/                 # Maestro's run reports
  android/phone/01-home.png, 02-playing.png, 03-playing-dark.png
  android/maestro/, android/emulator.log
```

Captures are shared: every clone's `.screenshots` is normally a link to this project's folder in the
matrix workspace's `matrix-artifacts` store, so a capture taken in any clone is the one every
clone uploads, and no clone recaptures to release. A capture through the store records its
commit and status in `.screenshots/capture.json`; the capture scripts replace files inside
`.screenshots` and never remove the folder or that record. The `listing` lanes upload the
screenshots (see [releasing](releasing.md)) and refuse a capture that is still running,
failed, or taken from uncommitted changes, or one that starts while they copy.
