## Repository layout

Keep application code and its focused tooling in `ios/`, `android/`, `web/`, and `l10n/`.
Store lanes and their helpers, tests, and metadata remain together in `fastlane/`.
The [script directory](../scripts/README.md) groups other repository-owned commands by
purpose. Update callers, relative paths, native build inputs, tests, and documentation
when moving a script. Package scripts remain the normal entrypoints where available.

Shared workflow commands and managed skills come from the exact-pinned agent-tool;
keep nc-specific policy in `agent-tool.json` and the application gate in its hooks/CI.
Detailed application behavior lives in [architecture](architecture.md), language
maintenance in [localization](localization.md), and publishing in [releasing](releasing.md).

## No binary files

Nothing binary is committed; the hooks reject it (`bun run lint:binary-files`).

**Images** are generated from two SVGs in `assets/brand/`, and the outputs are gitignored:

| Source | Becomes |
|---|---|
| `assets/brand/logo.svg` | The mark, an LCD equalizer drawn full-bleed so its columns touch the icon's bottom edge: the iOS app icon and launch screen logo; the Android adaptive icon foreground, themed (monochrome) icon, and notification icon; the favicon; the logo beside each app's title; the Play Store icon and feature graphic |
| `assets/brand/background.svg` | The iOS app icon backdrop and full-bleed launch screen; the Android adaptive icon background and splash color; the favicon, title logo, and Play Store graphics |

The `images` section of `agent-tool.json` declares every output's size, layers, and
destination, and `agent-tool images` renders them
([reference](https://github.com/a2f0/agent-tool/blob/main/docs/images.md)), with no image
tools to install. Builds regenerate them when the sources change (an Xcode build phase and a
Gradle task before `preBuild`), or run `sh scripts/build/buildImages.sh`; `web/build.ts` writes the
favicon, and the `android listing` lane the Play Store graphics. To look at those, run
`sh scripts/build/buildImages.sh store --out .screenshots/android` (`--out` is relative to the
repository root). Android 12+ splash screens only take a solid color, so Android uses the
background's average color there. Android adaptive icons show the inner 72dp of a 108dp layer,
which the mark fills; its bottom row is stretched to the layer's edge so the columns still
reach the bottom under any launcher mask. Single-color renders (themed and notification icons),
the favicon, and the title logo leave out the mark's `unlit` group of dim segments.

**The Gradle wrapper jar** is regenerated by `scripts/dev/ensureGradleWrapper.sh`.

## Git hooks

`bun run hooks:install` installs the three hook bodies declared in `agent-tool.json`;
rerun it after hooks change. `bun run hooks:check` checks every managed file, and
pre-push also compares its own copied body so stale hooks cannot gate a push.

When migrating an existing clone from the old installer, inspect its effective hook
directory (`git config --path core.hooksPath`, or the common Git directory's `hooks/`).
After confirming the installed files are the expected repository copies, run
`bun run hooks:install --adopt` once. The shared installer backs them up and preserves
unknown hooks; resolve local hook edits before adoption. Later installs omit `--adopt`.

- **pre-commit:** branch name is `<type>/<name>` (or `main`); no binary files staged.
- **commit-msg:** Conventional Commits, header at most 50 characters, lowercase subject.
- **pre-push:** commits are signed with no `Co-authored-by` trailers; no binary files;
  ShellCheck; RuboCop; shared agent skills are current; localization is current; fastlane
  helper, web, and localization tests; web typecheck, build, and deploy dry run; Android
  debug build, lint, and unit tests; iOS simulator build, audio rendering checks, and player lifecycle tests on an isolated simulator.

Branch names use the configured Conventional Commits types, with `main` exempt and no
additional length cap. Native Git ref rules also apply. Commit headers keep the existing
50-character limit, lowercase initial subject, no terminal period, and generated-message
exemptions. A small commit-message adapter preserves nc's lowercase scope grammar,
counts the whole header including a PR suffix, and skips leading blank/comment lines
before applying shared policy. Signatures must be present and not provably bad;
local key trust is not required.

Pre-push validates every destination branch from Git's ref tuples. Trust checks exclude
commits reachable from the named remote's tracking refs even for an existing branch update,
so integrating previously published mainline commits does not revalidate historical policy.
New local commits still undergo signature, attribution, and subject checks. URL-only pushes
use their remote tip, or local `main` for a new branch, because they have no named tracking refs.

`bun run check` keeps the full application gate in `scripts/testing/check.json` and records
per-step logs and source fingerprints. A failed command or changed source fails the group.
Use `bun run agent-tool runs list --head <commit>` to find stored receipts. CI passes the actual
PR branch explicitly and runs the same checks; `CI gate` remains the single required check,
with every lint, Android, iOS, and web job required to succeed.

## Screenshots

```sh
sh scripts/testing/takeScreenshots.sh [ios|android]
```

Drives the app with the Maestro flows in `maestro/screenshots/` on dedicated simulators and
a headless emulator, with a fixed 9:41 status bar, in light and dark appearance. Android
runs the minified release build, signed with the debug key. Writes store-sized PNGs (no
alpha) to the gitignored `.screenshots/`: iPhone 6.9" (1320x2868), iPad 13" (2064x2752),
and Android phone (1080x1920, within Google Play's 2:1 limit). iOS captures use the full
rectangle without black device corners. The `listing` lanes upload them
(see [releasing](releasing.md)).
